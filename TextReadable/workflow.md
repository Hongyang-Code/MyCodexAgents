# 审校工作流

## 1. 接收与冻结

按 interface.md 读取原文、读者背景、文体和保护要求。只有 original_text 必填；读者未指定时以原文预期读者为准，不凭空降成科普或改成另一文体。输入为空、不可读或无法完整获得时，返回 needs_clarification，不猜测内容。

将最初完整输入固定为 original_text，候选文本初始等于原文，修改轮数为 0。调用方传入原文与候选时，原文仍为唯一语义基准；先查候选有无漂移。已有用语偏好不能自动授权改动原文主张。

识别原文的结构、陈述、引用归属和保护片段。长文本可分块，但必须保留标题、前后文、指代和交叉引用；分块不重置总轮数。不能只审查局部就宣称全文通过。

## 2. 建立简短语义清单

按句、段、表格单元记录可追踪的位置，不必逐字制作巨表。必须覆盖：

- 谁在什么条件、时间和范围内，对什么对象作出什么判断。
- 数字、单位、符号、比较基线、指标方向、绝对或相对变化、否定及量词。
- 因果、相关、转折、递进、先后、假设、必要与充分条件。
- 事实/作者声称/推测/建议的区别，概率与确信程度，限制和例外。
- 引用对应的主张、说话者、核心术语、文体及有意义的强调。

原文已有事实错误或结论越界，不会因进入语义清单而变得可靠。记录为源文本问题，保留其原貌并返回调用方处理。

## 3. 初检与最小修改

逐项执行 checklist.md。原文全部达标则通过，轮数为 0。不以主观偏好或字数减少作为必须修改的理由。

优先处理需要反复回读的句子：长定语、嵌套从句、远距离主谓、含糊指代、多个逻辑关系挤在一句、重复铺垫、抽象名词堆叠。先使用原文已有词语，拆句、重排或分段。仅在上下文唯一确定时补出被省略的主语或展开指代。

纯粹重复的表述可合并，但其语义、强调作用和引用归属都必须保留。标题或列表也可能新增范围或重要性判断，应一并审查。论证缺口不靠润色填补；术语缺少必要定义时只提示，不能擅自加入知识。

若解决问题必须改变信息、判断强度或补充缺失知识，停止相关改写并返回 needs_clarification。可以完成其他无歧义部分，但整体不能标为 passed。

## 4. 有界循环

每次实际修改候选文本计 1 轮，随后必须独立切换到审校视角：

1. 检查可读性和用语严谨性，确认修改解决了具体问题。
2. 原文 → 候选：逐项核对原文信息有无遗漏、弱化、拆散后丢失限定。
3. 候选 → 原文：每个主张是否在原文有对应，是否新增解释、因果或确定性。
4. 核对所有保护项、引用位置、跨段指代、逻辑关系和格式。
5. 发现漂移则标记候选不可交付；下一轮从语义保真版本修复，不在漂移稿上继续扩写。

所有必查项满足才能 passed。无需为了用满轮数继续改。上限包含所有修复尝试；最后一轮结束后仍须复查，不能“再改一下”超出预算。连续两轮没有解决任何实质问题，或重复出现已淘汰版本，则以停滞结束。

始终保留最后一个已确认语义保真的候选；原文是零改动基准，但可能在语言严谨性上不合格。没有更好安全候选时退回原文，并明确未通过，不能回传已发现语义漂移的稿件。

## 5. 全文复查与返回

分块审校后额外做一次全文一致性检查，该检查不消耗修改轮数；需要修改时仍计入剩余预算。预算耗尽且发现新问题则返回 not_passed。

按 interface.md 返回状态、正文和必要问题。未验证外部事实不能写成“已确认所有结论可靠”。调用方后续更改正文或原意后，原来的通过状态不再覆盖这些改动。

调用方修正源文本后，可明确建立新的 original_text 版本再次调用。记录原文变更原因，并遵守调用方总体迭代预算；不得悄悄用每轮新原文规避上限。

## 各阶段的可选约束门槛

收到 output_requirements 时先按 requirements.md 检查输入原文是否满足内容要求，逐项记录覆盖位置。初稿已缺少的实质信息返回调用方处理，不能进入润色后直接标合格。内容要求、格式要求与原文一起冻结；每轮修改后双向保真检查之外，复查每项要求及每个具体事件/章节。交付前执行结构脚本（有授权缓存路径时），把结果绑定到最终文件；未提供要求则这两类检查不适用。此门槛加入现有各步骤，不增加轮数或审校批次预算。
