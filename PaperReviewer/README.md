# PaperReviewer

两位独立子智能体模拟专业审稿，主任务裁决质疑，修订子智能体改稿，主任务复查。接受段落、章节或全文，返回相同范围的修订稿，附必要未决事项。默认最多3轮，用户可指定N；每轮都有内容与可读性检查，最后复用TextReadable。

## 使用模板

```text
请读取 E:\MyCodexAgents\PaperReviewer\AGENTS.md 及其要求文件，审查并优化以下材料：
【文本或文件路径】

研究领域：【填写；可从材料推定时可省略】
目标会议：【填写；未指定则使用该领域通用高标准审查】
审稿轮数：N=3，最多3轮；问题已解决可提前结束。
输出：与输入范围对应的完整修订文本，同时给原稿到终稿的累计修改清单，逐项说明位置、修改前后、修改方式、原因与含义影响；另列审稿回应及未决事项。
特别关注：【填写或删除】
不得改变的内容：【填写或删除】
请完成内容审核与内置TextReadable审校，不编造实验或引用，不自动提交推送。
```

需要恰好N轮时写“round_mode=exact，执行N轮审查；无须修改时记录无修改”。证据阻塞或用户停止仍可提前退出，报告实际轮数。N是正整数，默认max模式。

## 工作边界

每轮两位审稿子智能体使用新上下文独立提交，分别关注方法/创新与实验/证据；独立修订者按主任务裁决返回候选，主任务统一保存。多智能体仍不等于真实会议评审或不同基础模型。用户指定会议时核查官方指南；A会标准因领域、会议和论文类型而异。质疑分为成立、部分成立、不成立、证据不足，不为挑刺而造问题。

PaperReviewer依据证据修订研究表述并记录语义变更；TextReadable对冻结后的修订稿做保真润色。需要新实验时给待办，不把未发生的结果写进论文。重大研究设计变更允许先形成独立拟议方案与验证待办，不并入正文充当已实现成果。

PDF无法保证原版式直接编辑；优先提供LaTeX、Word或Markdown源文件。仅PDF可交付完整Markdown修订稿并注明图表和版式限制。未读完整材料时只交付已处理范围。

真实输入、各轮稿件、回应与记录仅本地保存在outputs/，不入Git。用户要求仅对话时不落盘。未解决问题不会因达到轮数自动变为通过。

## 验证

`python -m unittest discover -s PaperReviewer/tests -p "test_*.py" -v`

scripts/check_run.py验证轮数、记录、状态、问题流转及最终文件哈希。它不调用模型，不自动运行审稿流程，也不能证明证据成立或科学判断可靠。默认没有定时任务或Git自动同步。

所有正文修改（含TextReadable）必须有累计修改说明。检查器绑定原稿、终稿、清单及角色实际提交；本地保留逐轮记录，最终以累计清单为准。用法见change-tracking.md。

当前多智能体升级已通过40项测试，并完成段落和完整合成稿各2轮实际子智能体试运行。验收范围与限制见VALIDATION.md；输入、修订正文和累计修改清单保存在本地outputs/，不自动上传。
