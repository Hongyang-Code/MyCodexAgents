# 追踪流程

## 1. 确定范围

解析领域、任务、对象、排除项和时间范围。用户只给宽领域时可按主要子方向检索，不自行限定成某种方法。没有领域时按AGENTS.md的优先级推定，并记录推定依据；例如一篇图像配准论文只能支持“图像配准”的暂定检索，不能确定用户仅研究医学图像或仅使用深度学习。

建立中英文术语、同义词、任务和对象组合。报告首部显示实际检索范围和排除项，防止关键词偏移。仅在明确存在可访问历史时读取相关记录，不默认搜索全部私人任务。

以检索开始向前取7×24小时；用户指定日期范围则解释包含端点和时区。建立 outputs/YYYY-MM-DD_HH-mm-ss-领域短名/，清理Windows禁用字符，冲突追加序号。先读 outputs/paper-index.json（存在时）；按领域键隔离历史，不把其他领域的上次筛选当成本领域全部覆盖。

## 2. 四线检索与日期口径

1. CCF及其他重要期刊会议：先核对CCF当前官方目录，再查看与领域相关的出版方online-first/early-access、正式论文集与会议官方公开入口。其他重要venue根据领域学会、专业范围和领域关键工作的发表渠道给出选入理由，列在sources.md；不虚构“CCF收录”。不默认只查A类，也不要求CCF穷尽跨学科工作。
2. arXiv：按任务术语、相关分类、交叉分类和同义词查询，核对摘要页、版本历史及公开时间。预印本身份如实标记；作者写“accepted”不能替代会议官方核查。
3. Hugging Face：检索Papers／Daily Papers的相关论文，回到原论文核实日期、版本和内容；记录发现页链接。推荐、收录时间和社区热度均不作为新论文或质量的证据。不单独追踪没有对应论文的模型、数据集或Space。HF自动生成的摘要只作线索，不能代替原论文。入口跳转到其他日期或读取失败时记录实际页面及缺口，不声称完成该日扫描。
4. 其他相关论文：其他期刊会议、workshop、其他预印本平台、可识别的技术报告和OpenReview公开投稿。明确同行评审状态；搜索引擎、聚合榜单只作线索，回到论文原始入口。

CCF目录入口：https://www.ccf.org.cn/Academic_Evaluation/By_category/ 。记录本次采用的目录版本和访问日，不能照搬旧缓存级别；目录用于来源导航，不代替单篇质量评估。若领域不适用CCF，说明并以领域相关venue补足。

“近一周”按论文首次公开或本期正式发表的可验证日期纳入。首次公开包括预印本，正式发表是另一种状态变化。会议举办日、数据库抓取/入库日、DOI注册日、新闻转发日都不能自动当成论文发布日期。online-first已有旧版本、后续卷期分配不当新论文。

arXiv保留v1日期与当前版本日期；公开公告与提交时间不同时明确口径，无法确认公开时间时标明使用提交历史代理及边界不确定性。arXiv v1也可能是已发表旧文的补上传。检查PDF页眉、journal reference、DOI及作者机构记录，不能把平台首次上传当作作品首次公开；无法核实实质差异时不纳入更新。

仅查updated会混入旧稿，因此必须区分：
- 首次公开：本期首次公开的新论文。
- 正式发表：早有预印本、本期正式发表，注明“已有预印本”，不称全新工作。
- 实质更新：旧稿新增关键实验、纠错或结论变化，仅在重要且已核实版本差异时纳入同组，标记更新；改排版、元数据或仅版本号变化不纳入。
- 无法核实日期：留待核查线索，不填补本期新论文清单。

按DOI、arXiv无版本ID、题目作者与正文核对身份，跨分类、跨来源去重。一篇仅一条；展示归组优先级为选定期刊会议 > Hugging Face > arXiv > 其他。HF发现且不属于选定期刊会议的arXiv论文归HF，但保留预印本身份。来源记录保存全部发现渠道；显示板块顺序仍为期刊会议、arXiv、Hugging Face、其他。归组优先级不表示质量。记录所有别名，保留稳定ID，不仅凭近似题目合并不同论文。

## 3. 分层阅读

对全部候选先读身份元数据、摘要、结论（可得时）和版本信息；排除仅关键词碰巧命中、旧闻、无法识别论文身份的条目。短名单继续阅读方法总览、关键实验表与条件、局限，必要时核查官方代码和1—2篇决定创新判断的前作。声明“建议精读”前优先完成这层核查。

读不到正文时可以保留确实相关的新论文，但须标“摘要级”：方法和数值保留作者归属，可靠性只能说明证据不足，不能编出实验设置。看过结论或部分表格不等于阅读全文。不对每篇扩展完整文献树，不逐公式解释或试运行代码。

为每条记录已读章节、关键主张和数字所在页/表、链接与访问日期。PDF表格或双栏提取有歧义时检查对应页；未能消歧则省略该数值并说明。仅“看到了仓库链接”不算检查源码。

## 4. 筛选、评估与输出

依据assessment.md评估。默认覆盖领域主要子方向，不用名气或引用数替代相关性。关注信号仅在有可核查证据时报告（如已核实独立复现、后续工作）；无信号时使用“新近工作”。不强行做热点趋势、领域已达共识或影响力预测。

按模板输出，每篇使用独立三级标题，基本信息独立成段，六个字段逐项换行并留空行。禁止把多项压在同一段。先用速览概括“核心贡献+作者主要发现/限制”，其余字段补充必要细节，避免六次复述。阅读建议默认精读/略读；材料确实不足时允许暂缓判断，须写原因，不能把未知评成低质量。

某组无论文时写本次未检出符合条件的论文，并说明检索范围；不能说该领域本周没有新论文。论文集集中放出时按相关性逐条筛选，不把整本论文集当一篇，也不因数量多设隐性配额。

## 5. 审校、保存与持续记录

先核对身份、版本、日期、新旧归类、作者主张和数字比较条件，检查全文来源及重复论文。按 text-readable-requirements.md 冻结内容和要求，执行TextReadable、结构脚本和本目录条目检查脚本。缺失事实回到来源处理，不能让语言审校补造；每期最多2批。

保存 report.md、sources.md、papers.json 和 .cache/下的original-text.md、output-requirements.json、text-readable-result.json、quality-review.md。papers.json至少记录稳定ID、领域键、题目作者、DOI/arXiv及别名、来源组、全部发现渠道及链接、各版本日期及口径、已读范围、关键证据位置、代码检查范围、建议、较上次变化。所有结果仅保存本地。

通过后更新paper-index.json，先备份旧索引；保留既有论文和旧报告、更正前说法及依据。没有实质进展不重复包装成新发现。完成四线扫描及明显缺口补查后，补检主要重复/次要时停止；受工具或材料限制提前结束要标有限覆盖。最终正文必须来自已审校版本。

## 发表信息与共享目录

读取 ../shared/references/ccf/README.md，使用其中的目录和查询脚本。每篇基本信息必须有作者、发表渠道简称、等级（含目录年份或不适用/待核实说明）、日期及版本状态、已读范围。按正式 venue 全名匹配，保留原始来源与等级查询记录；预印本不套用拟投会议等级。当前副本与官方勘误的一致性限制必须披露。papers.json 保存 venue_full_name、venue_abbreviation、ccf_grade、ccf_edition、ccf_lookup_status。
