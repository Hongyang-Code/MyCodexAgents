# 检查与改写流程

## 1. 接收与冻结

接收文段、章节或全文；可选指定 section_type、目标刊会、上下文、仅检查、max_rounds、保护项及输出位置。缺少完整上下文时说明实际覆盖范围，不假定已有消融、图表、数据或其他章节。

将最初原文固定为 original_text。建立稳定单位ID（P01等，可按段落或章节），标明章节类型及判断依据。记录每项事实、假设、比较、数量、条件、引用归属及逻辑关系。重排可以改善表达；原意的限定作用域必须保持。若需要跨段重组，记录每个原单位的去向，不能借重组漏掉原文。

## 2. 诊断

先查内容矛盾、数字歧义和结论越界。不能因为保留原意就认可原文科研主张。此类疑点只根据现有材料判断，缺实验或全文时标明未核验。

再按 style-guide.md 对当前章节的适用规则逐项判断。每条问题至少写：原句/位置、问题类别、规则ID、具体偏离、为什么影响阅读或论证、建议改法。风格依据引用 references/corpus.md 中的论文ID和章节；不把作者个别用词当硬规范。

章节“通常有结果”而输入没有结果时，先判断是否为完整章节。真正缺少事实时指出待补，不生成结果来完成结构。短摘录、中文稿、没有公式的段落及无对比的任务按适用范围检查。

风格判断用以下词语，并说明主要依据：

| 判断 | 含义 |
| --- | --- |
| 基本符合 | 适用核心特征已满足，未发现需要修改的明确偏离 |
| 部分符合 | 主线合理，但有可定位的冗长、组织或衔接问题 |
| 明显偏离 | 主要论证被空泛表述或无组织堆叠遮蔽，需要重组现有内容 |
| 材料不足无法判断 | 文段过短、严重歧义或缺关键上下文，不能作整体判断 |

不能用风格判断替代内容核验状态。即使语言接近参考论文，科研内容仍可能存在问题。

## 3. 有界修订

只对明确问题作必要修改。句式、词汇与组织参考风格档案，优先使问题、机制、比较和证据的关系清楚。不得凑关键词、添加问句或重复 In order to 等表达。

每轮独立切换到审校视角，执行 quality-check.md：原文→改稿检查遗漏；改稿→原文检查增补；核查语气与逻辑；复查适用风格规则和阅读难度。始终回到最初输入，不以逐轮稿为唯一基准。发现漂移的候选不可交付；在剩余预算内修复，或返回最后一个已确认保真的版本。

每次实际改稿计1轮。默认最多3轮；符合即可提前结束。连续两轮无可执行改善或版本往返则停止。仅检查或原文达标可为0轮，不能伪造修改。

## 4. TextReadable 与最终复查

按 text-readable-requirements.md 传入最初用户原文、风格候选稿、展开的内容约束及真实的格式约束。上下文只用于理解，不能转移新事实到正文。语言审校总预算独立记录，每批最多3轮、整份任务最多2批，不随风格轮数重置。

若 TextReadable 指出源问题，回到该原句处理；不能悄悄改成更强或更弱的科学结论。若后续修订是风格改动，也计入剩余风格轮数；超限则报告状态。最终检查语言审校是否损坏问题—方法—证据的关系或加入生硬风格词。

## 5. 交付与保存

按 templates/report.md 交付判断、具体问题、完整修订正文、累计前后对照和未决事项。风格依据置于诊断说明，不把参考论文引用添加到用户正文。

英文正文保持英文，解释用简体中文。正文未经修改时照原文返回并写“本次未修改正文”。有源问题时把受限正文和待核查事项分开，说明仍未解决的内容问题。

保存时优先新建 outputs/日期-短主题/；保留原稿、终稿、报告和审校记录。来源下载仅用于研究风格，不纳入Git。配置可以版本管理，当次无同步请求则不提交推送。scripts/check_result.py仅作记录与保护项检查，人工风格判断、语义核查及 TextReadable 必须实际执行。
