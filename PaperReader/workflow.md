# 阅读工作流程

## 1. 材料和身份

接受本地 PDF、URL、DOI、明确题目。核对原题、作者、版本、年份、venue、DOI/稳定标识，记录检索日期。优先出版方、会议官网、作者或官方仓库。预印本年份与正式发表年份不可混用。

同名候选无法消歧时询问用户。普通来源缺失先尝试其他合法公开来源；不绕过访问限制。全文仍不可得时，明确“摘要级/部分阅读”，交付可支持的内容，其他栏目写缺失及影响。不用常识猜论文细节。

创建本地产物目录；原文不必复制用户已有文件，可在 sources.md 记录绝对路径和版本。下载的文件放论文目录 .cache/。记录哪些页、附录、补充材料和外部来源已实际读取，不能把检索到等同于已读。

## 2. 阅读和证据

先通览结构与图表，再读方法、实验、结论及相关附录。PDF 双栏、公式、表格与图注必须结合页面视觉核对，不能只信文本提取。

按 templates/sources.md 记录来源和关键主张。原文位置写章节、印刷页码或 PDF 页序号（明确区分）、表/图/公式编号。外部来源写稳定链接和访问日期；仓库检查记录分支/commit（可获取时）。重要引用就近放在正文，不只放文末。

## 3. 贡献和阅读价值

解释领域与任务 → 现有方法缺口 → 作者解决思路 → 核心模块 → 关键假设。区分作者描述的缺口和与前作核查后的差异。创新可以是问题、方法、理论、数据、系统或实证发现，不强行归结为新模块。

阅读建议使用精读、选读、略读、暂缓判断，并解释推荐章节。精读优先考虑实质创新与合理前景、领域基础或转折价值、可直接借鉴的关键方法。默认与用户相关，但不要虚构用户具体课题。领域地位需要后续继承/采用等证据，不能单凭名气或 venue。

分别讨论发表时的贡献和当前使用价值。近期论文缺少后续引用不能直接扣分；未来前景必须标为分析，写依据和限制。

## 4. 可靠性：证据能支持多强的结论

对每个核心主张判断：证据较充分 / 仅在特定条件下支持 / 证据不足 / 暂无法判断。说明具体证据，不给总分或假精确概率。

| 维度 | 必查内容 |
| --- | --- |
| 开源 | 实际源码还是占位页；训练、评估、配置、权重、数据处理、许可证；仓库存在不等于资源可下载 |
| 复现条件 | 环境、版本、划分、预处理、超参数、种子、计算资源、执行步骤；未运行不能声称成功复现 |
| 公平比较 | 同数据/划分/指标定义/测试策略；额外训练数据、预训练、规模、参数、算力、调参预算；结果抄录还是同设置重跑 |
| 结论支撑 | 消融是否控制参数/算力；重复实验、误差范围、样本量；显著性、选择性报告、失败案例与泛化范围 |
| 外部一致性 | 关键 baseline 与原论文/官方结果是否一致；差异先排查设置与版本，不把异常直接写成造假 |
| 泄漏与混杂 | 测试集参与选择、训练测试重叠、预训练污染、后处理、额外监督等；无证据只能记风险/未知 |

对比表注明指标越高/低越好、数据划分、资源与单模型/集成等设置。绝对百分点变化与相对变化分别计算。不能把不可比结果直接排成优劣；未报告误差时不声称显著提升。

## 5. 报告和相关工作

使用中文主体报告模板。论文摘要提供判断，正文提供可追溯依据，不逐段复述论文。术语第一次出现解释含义；公式明确符号、假设和关键步骤。作者的直观解释与实验支持程度分开写。

相关工作默认 3～6 篇，兼顾论文引用的前作、引用本文的后续工作、直接相关方法。每篇提供作者—年份—原题—venue（核实到的部分）、DOI/arXiv/官方链接、与本文关系。声称“引用本文”必须在后作参考文献或可靠引文记录核实；只有方法相关就标“相关方法”。仅检索到摘要时说明核查范围。不声称穷尽所有后续工作。

潜在问题分作者承认、证据支持的局限、待验证疑点。未来工作分作者方向和智能体建议；每个建议包含动机、最小对照实验、评价指标及适用条件，不能保证创新或收益。默认精选 2～4 个有根据的方向，不凑数。

理论论文关注定理条件、证明和反例；综述关注检索覆盖、纳入标准和分类；数据集论文关注采样、标注、偏差、许可与划分。删除不适用训练/Loss/SOTA 栏，不杜撰。

## 6. 图与交付

按论文真实章节组织图：根为短题目，一级为章节，二级为该章最重要内容。默认 2～3 层；长论文合并次要小节，保持顺序。中文为主，保留必要原题/术语。图中不能引入正文没有的结论。

使用 JSON 图数据和 scripts/render_mindmap.py 生成 PNG，不使用生成式图像模型绘制文字图。中文字体缺失时明确报错并寻找可用字体；不得交付乱码图。渲染后必须实际看图，过长就压缩节点或重新排版，不能仅靠缩小字号。

执行 quality-check.md 的全部检查、修改与复查。在 .cache/quality-review.md 保存简短审校结果（发现、修正、证据位置、复查状态），不保存冗长内部思维过程。交付仅给修订版、必要限制和未决问题。

## TextReadable 输入与最终版本

执行 text-readable-requirements.md：起草前展开内容与格式要求，冻结后与 original_text 一起传入；审校结果必须含逐项覆盖位置。最终文件运行结构检查，再复查内容实质覆盖。不得在对话交付时另行压缩掉已审校栏目。
