# 新闻简报工作流程

## 1. 确定范围与本地批次

读取实际当前时间。默认窗口为检索开始前7×24小时；指定纯日期区间包含起止两日，结束时间采用次日零时排他边界。进行中的当日只覆盖已发生时间，未来日程不能写成已发生事件。记录时区、时间解释及核查截止点；来源只有日期时保留该精度，不编造具体时刻。边界当天时间未知的事件注明边界不确定，不擅自换算。

输入可含时间、地区、领域、关键词。多个地区取并集，多个领域取并集；地区与领域之间取交集。关键词默认至少匹配一个，和已有地区/领域条件共同限制；不清楚词义且影响范围时澄清。国际事件的直接涉及地区及有证据的影响地区可用于匹配，不能为扩大收录随意贴标签。

在 outputs/YYYY-MM-DD_HH-mm-ss/ 建立一期目录，重名追加序号，不覆盖旧文件。保存 report.md、sources.md、events.md、.cache/quality-review.md。历史稳定事件索引位于 outputs/event-index.md；先读取旧索引，没有则作为首次追踪。

## 2. 广泛扫描与筛选

先按 taxonomy.md 覆盖地区和领域，可组合查询但需记录每类实际扫描情况。优先原始机构、可靠通讯社、地区媒体和专业来源，避免仅依赖一种语言或单一媒体首页。新闻网站菜单/搜索摘要仅供线索，进入原文核对后才作为事件依据。

按公共影响、紧迫性、实质进展及信息价值筛选，不打主观总分，不设条数配额。低热度但影响明确的事件可收录；重复评论、宣传口号、无变化的表态通常不单列。检索到某类而未纳入事件，应记录“无符合项”或“证据不足”，不把未查到等同于没有发生。

检查报道时间与发生时间。事件较早但本期有救援更新、调查结论、政策落实或实质谈判等可纳入，背景明确标为范围外。纯转载和没有新事实的回顾不纳入。

完成各地区/领域扫描、重要线索追查后，再补查明显缺口。补查主要返回重复或次要信息即可结束；工具限制或来源缺失时也可停止，但标记部分覆盖，不能伪装已穷尽。

## 3. 事件合并与来源核查

用参与者、地点、主题、起始事件核对身份，不仅比较标题。每个事件使用稳定的ASCII标识 evt-YYYYMMDD-short-slug，首次以可核实起始日期命名，未知用首次收录日期并说明。标题变化保留ID；不同事件冲突追加序号。后续收录先对历史索引，不另造重复事件。

为每个关键主张记录来源URL、发布/更新时间、原始机构或转载链、实际阅读范围与核查时间。重大或争议事实尽量用独立来源核对；只有单一来源时保留归属并明确限制，不假装已交叉证实。

先查原始公告、公开文件、数据及讲话全文，再结合可靠报道。机构自己的指控、推测和评价只能证明它作出该说法。保留相关方主要回应；未获取到回应写“本次未获取”，不能断言从未回应。

数字冲突先核对截止时刻、统计口径、单位、修订版；无法消解则明确呈现。译写保留专名、否定、条件和语气强度。遵守来源引用与版权限制，不大段搬运报道。

## 4. 起草与持续更新

使用 brief.md，保留时间、地点、人物/机构、起因、经过、结果/状态、影响、争议/未知、后续节点及来源。按模板保留独立栏目行，尤其“结果／当前状态”与“影响”分开；每件事件都须逐项核对。没有人物或具体地点时写机构/影响范围，不强填。

起因须有来源；关系先后不等于因果。已发生影响与预测分开，预测注明谁提出、何时、何种条件。智能体自己的解释、建议和立场不进入正文。引用不因措辞中性而失去归属。

每期按公共影响、紧迫性和进展排序，说明定性标准，不用偏好政治立场排序。地区与领域索引均链接同一事件锚点，正文只出现一次。

events.md记录本期ID、旧报告链接、新进展、来源及更正。新报告通过后更新event-index.md中的最近收录路径和状态；保留更正记录及旧报告，不删除原说法证据。证据不足的候选只留来源记录，不写入已核实事件索引。

## 5. 审校与交付

执行 quality-check.md 的事实/归属/偏差检查；冻结正文后执行TextReadable，再核对索引、标题、时间线、引用和结论。文本必须以最终核查状态为准。

全部检查通过则交付；重要核查缺口未解决时明确“有限覆盖/部分核查”，列缺失和影响。事件多时保留完整本地文件并分批展示，不能用预设条数截断。不要将内部审校记录和全部检索噪声贴给用户。

## TextReadable 输入与最终版本

执行 text-readable-requirements.md：起草前展开内容与格式要求，冻结后与 original_text 一起传入；审校结果必须含逐项覆盖位置。最终文件运行结构检查，再复查内容实质覆盖。不得在对话交付时另行压缩掉已审校栏目。
