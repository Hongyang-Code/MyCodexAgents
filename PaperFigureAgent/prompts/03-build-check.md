# 阶段3：构建、验收与交付

使用run.py与工具契约构建未压缩mxfile。所有节点端口、边标签、文字、分组须原生可编辑。输入schema由你生成，不要求用户提供。组件库包含过程、数据、判断、状态、存储、张量、注释、成组图像；超出能力时扩展原生组件并测试，不能静默位图化。

先 check，再原生 render。失败读具体诊断并修复源文件；不要只改PNG。不影响科学关系的几何优化仍须检查拓扑。路线优化依据长度、折点、交叉、避障与文字冲突；必要线路不能为分数删掉。复杂分组、端口、箭头和打印字号由实际渲染复查。

分别记录：

1. 结构：XML、ID、引用、几何、父子、端口。unsupported对象写明，不擅自丢弃。
2. 科学：对照来源与图谱，查漏边、倒转、额外节点、错误边类型、证据缺口。自动检查只做内部一致性。
3. 几何：对齐、连接附着、流程穿字穿框、标签冲突、交叉是否明确、折点理由、空白与同类素材尺寸。近接/复杂曲线需目视判断。
4. 原生：官方draw.io实际打开/导出，保存source/output哈希。只导出成功还不等于看过图。
5. 视觉：全图与最终印刷尺寸分别查看。说明层级、阅读路径、紧凑度、配色语义、核心贡献、文字可读。必要时查看局部放大，不用放大截图替代印刷尺寸判断。
6. 编辑：在副本中实际改模块文字、移动模块和图像组、保存重开、检查连接附着。有工具就实测；无交互环境或启动失败记not_run，不把XML patch测试称为UI实测。
7. 历史：所有active要求逐项核对，局部修改保护无关对象与其他页，重查有效的新旧要求。

最多三轮优化。每轮更新源、checkpoint --optimization、重新导出、复查。达到上限仍有硬错误只交问题版本，说明具体对象、缺失事实及修复方式；不无限循环。

host-review.json写实际证据，字段见state-spec.md。deliver重新运行确定性检查并核对基准/图片哈希。完整交付与问题版本分目录保存。既有示例、别的任务或旧版审查不能搬用。
