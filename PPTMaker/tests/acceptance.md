# 首版验收场景

自动测试：从仓库根运行 `python -m unittest discover -s PPTMaker/tests -p "test_*.py" -v`。

## 必须实际执行

1. 模板改制：自建简单模板，先查看源页面，改内容并保留尺寸、字体、位置及固定页脚，确认旧正文/备注清除。
2. 材料重组：给密集科研材料，生成方法流程、结果证据边界、成品图片页面；原生表、图、文本和连接线可检查，成品图正常放入。
3. 主题调研：先读取公开原始来源，再形成简短组会PPT，备注含来源和限制；不编造实验。
4. 故障注入：独立副本加入长段落、越界、单位/数值错误、无依据结论及反向连接线。结构检查与内容/画面检查分别记录，再从正确源重建并逐页复查。
5. 语言审核：冻结逐页文案，展开全部S编号、屏幕条件和备注来源。TextReadable不得删条件、改单位、将假设改为事实；错稿只能返回源问题或修正后重查。
6. 文件绑定：最终PPT或图片改动使旧记录失败；最后语言批次只审样页、漏页审核、预算超限、缺确认记录均阻止最终通过。

## 人工判断的边界

新增严格听众审查验收：缺审查、缺听众依据、缺维度、漏页、旧PPT/文案哈希、超轮次、未解决问题、缺复查依据均须被交付检查器拦截。有证据驳回不成立的质疑允许通过，不强迫改动。真实制作时还需以目标听众角色检查过强结论、比较条件、反例、图表误导和跨页逻辑，修订或返工后对新文件复查；记录测试通过不能替代该专业检查。

- 数字存在不证明科学主张正确；“所有场景有效”需回源核查，不能依靠词表或评分。
- 同样数量的连接线可能接反，实际图示与方法逻辑需对照。
- 文字少不保证可读，渲染成功不保证美观，脚本通过不保证PowerPoint显示或编辑行为。
- 公式编辑、复杂外部母版、动画、多媒体、长篇答辩等能力未实际验证时不得声称覆盖。
- 不因成品图片图内文字不可编辑判失败；不允许新制表格/整页内容图片化冒充原生对象。
