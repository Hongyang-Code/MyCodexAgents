# 严格听众审查：输出前的必要门槛

## 审查基准

根据当次听众、用途、目标和时长，记录合理可能遇到的最高专业水平、最严格审查角色及依据。例如科研答辩可采用该方向资深教授或答辩委员的专业要求。未指定具体人物时不冒充真实专家，不声称专家实际参与。听众不明时明确推定及理由，有实质歧义再询问。

严格意味着要求主张可追溯、论证经得起反驳、表达准确清楚。不能编造问题、要求不相关的实验，或把非科研场景一律改成论文答辩。页面仍须让原定听众容易理解，不能用专业术语和大量细节制造严谨的外观。

## 执行时点与范围

逐页方案阶段先预判关键质疑，在最后文字与视觉检查后冻结候选PPT、文案、备注、来源和预览。当前主任务切换至审查视角执行，不默认启动子智能体。代表页输出前审查已制作页面和它们依赖的上下文；整套交付前必须重新覆盖全部页面及跨页论证。

每页记录可能的核心追问、对应主张和证据位置、核查结果。没有问题也须说明审查依据，不要求凑问题数量。整套必须覆盖以下五个维度：

| 记录键 | 严格审查要求 |
|---|---|
| evidence | 结论是否有直接证据，数字、引用和归属是否可追溯；假设、未知与实测是否分清 |
| reasoning | 方法及推导是否正确，关键条件是否遗漏，因果、创新、显著性或泛化是否过度；存在什么反例或替代解释 |
| comparisons | 对照、指标、统计、消融及比较条件是否足以支持所述结论；非实验页面说明本任务适用的比较或核验方式 |
| communication | 标题、图表、流程、配色与视觉层次是否准确传意；最高水平听众能否迅速找到论点、证据和限制，普通目标听众能否跟上 |
| purpose | 整套能否在给定时长内完成呈现目标，重要质疑是否能由页面、备注或来源回答，内容取舍是否损害论证 |

不适用的具体子项写明原因，不能用“不适用”跳过整个审查。重要质疑必须查阅依据后裁决，不能凭“专家可能会问”判定材料有错。

## 问题、返工与复查

问题使用稳定ID，记录页面或整套范围、质疑、证据、影响、严重性、裁决及最小修正。成立或部分成立的问题须修正并验证；不成立的质疑保留反驳依据。证据不足保留未决，不能用强硬措辞或润色代替补证。

- 单页表达或图表问题：修订相关页并复查。
- 主线、证据链或方法解释有根本问题：回到材料核查和逐页方案返工，再制作与审查。
- 新证据无法取得：收紧结论且核查仍能实现原目标；若不能，停止交付并报告缺口。不得虚构数据或只补一句“有局限”掩盖错误。
- 内容变化重新核查来源并执行剩余TextReadable审校；任何变化重新导出、渲染受影响页面并核对整套一致性。新文件必须重新绑定审查记录。

默认最多3轮严格审查修订，初审和最后复查不计修订轮数。该预算不会增加已有视觉3轮或文字2批/每批3轮的上限；一次修改涉及多个类别时同时计入。任一所需预算耗尽、连续两轮无改善或缺少必要证据时停止，只向用户说明未通过项、原因和下一步所需材料，不主动提供未通过的PPT下载或预览。用户明确要求查看失败草稿时可以另行提供，并醒目标明未通过。

## 通过与记录

所有页面、五个整套维度均有审查证据；已发现问题均经修正复查或有据驳回；不存在未解决的事实、论证、表达或必要检查问题，才能标为pass并交付。纯个人审美偏好可作为样页确认议题，但不能据此放行已发现的阅读和视觉表达问题。

在review.json记录audience_review，绑定最终PPT和文案哈希，详见scripts/README.md。最终仅简述审查状态及重要修改，完整追问与处置留本地，不把冗长审查记录塞进PPT。

通过表示本次模拟审查未发现仍需解决的问题，不表示真实专家背书、答辩或评审必然通过。检查脚本只能拦截缺记录、旧版本和未闭环问题，不能证明专业判断可靠。
