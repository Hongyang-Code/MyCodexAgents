# 参考驱动的视觉设计与复查

所有制作与修改任务的固定必经环节，覆盖模板改制、材料重组、主题调研及局部修订。新设计或风格返工先查看匹配场景的优秀实例；模板改制以指定模板为依据；局部修订可复用已实际查看且适用的参考，但必须重新查看成品。不能以文字教程、品牌名或搜索缩略图代替实际参考页。

固定的是审查维度和交付门槛，不是单一配色、字体或布局。默认清晰、克制、美观大气，服从当次听众、用途及用户模板。每页不必都放大图，纯文字页也须有合适的层级、比例与阅读路径。

## 参考与设计决策

选择2～3类参考，覆盖方法、证据和整套节奏。记录原始链接、文件页码、实际看过的页面、可借鉴的具体关系及不适用部分。参考用于设计判断，不默认复制其素材、品牌、文案或科研结论。

逐页确定主视觉、第一阅读点、标题与证据的比例、颜色的语义作用。先问该页是否有独立存在的必要，再决定用图、表、流程或文字；材料薄弱时合并页面，不能靠放大数字或装饰把空白填满。方法图须解释关系，不仅把词语串起来。

简洁不等于空旷。克制不等于每页同一种布局。通过构图、信息主次、图文关系和疏密变化建立整体风格；不能只换色、加粗或机械对齐便声称重设计完成。

## 输出前对照

1. 同尺度查看参考页和成品页，记录主视觉、层级、图文比例、留白分组及阅读路径的具体差异。
2. 查看整套，检查布局是否随内容而变化、是否出现连续的散落文本块、缺乏核心图示或多余页面。
3. 查看原尺寸及关键区域放大图。单独检查可见字形中心、箭头、注释、边距、基线与数据标签，几何框对齐不能替代视觉对齐。
4. 将技术检查、专业内容审查、设计判断和用户风格认可分开记录。不得凭前两项通过推出后两项通过，不打无依据审美分，不冒称专家或用户认可。

明确缺陷须返工并复查；风格偏好仍由用户实际反馈校准。用户拒绝后保留旧版，标记其不再是推荐风格样例。既定修订预算仍适用，不靠增加参考流程重置。

## 固定审查维度与记录

逐页实际查看最终渲染，六个维度分别写具体发现和判断依据：

| 记录键 | 检查内容 |
|---|---|
| composition | 主次比例、视觉重心、分组和留白；无散落内容堆砌、无目的空白或挤压 |
| hierarchy | 第一阅读点明确；标题、核心证据、限定与注释层级清楚；阅读路径自然 |
| color | 配色匹配场景；强调色有明确角色；对比舒适；不依赖颜色单独传义 |
| typography | 字体、字重、行距、断行和字号形成统一层级；实际展示尺度可读 |
| visual_expression | 图、表、流程与文字各有必要性；关系表达清楚，不机械重复或装饰化 |
| alignment | 视觉对齐、箭头端点、标签关系、边距和间距准确；检查实际字形及节点 |

整套另记三个维度：consistency（字体、配色与设计语言一致）、rhythm（布局随内容变化、疏密与页面顺序合理）、reference_fit（与实际参考页对照，说明适用关系、取舍和差距）。不能靠评分平均掩盖任一项明确缺陷。

review.json新增必填design_review，具体结构见scripts/README.md。代表页记录覆盖本次展示范围；最终记录必须覆盖所有最终页面。每项状态为pass/fail/unknown；必要项不允许not_applicable。无图表页面在visual_expression说明文字表达为何适用。

发现的问题记录位置、表现、影响、修改和实际复查结果。明确缺陷必须修复；有据驳回的疑点保留依据。检查通过只能表示已完成当前审查且未发现未解决缺陷，不能宣称审美客观达标、专家认可或用户认可。用户风格反馈单独记录为pending/accepted/rejected，accepted须有明确用户依据，rejected阻止交付；直接制作无须额外征求认可。

最多3轮视觉修订，与其他视觉修复共用预算。修复后重新导出并查看受影响页面，复查整套一致性；任何最终文件变化均使旧版本记录失效。未通过只报告问题与所需条件，用户明确要求失败草稿时才交付并标明状态。不得追溯性补造旧报告通过记录。
