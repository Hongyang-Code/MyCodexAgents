# 数据与状态

所有真实数据放在 checkout 外的私有存储，仓库只存代码、合成测试与非敏感例配置。

## 追加事件账本

SQLite events：version（单调）、event_id（幂等）、kind、canonical JSON payload、occurred_at（含时区）。修改/删除触发器阻止普通应用覆写；数据库所有者仍可改文件，所以不宣称防篡改硬件保证。read-modify-write 必须携 expected_version，并在冲突后重读；同 ID 同内容重试返回原记录，不同内容报错。

## 证据及持仓

结构化快照携 screenshot/source 引用、as_of 和字段 confidence。持仓以完整代码映射确认份额；生产接入须另校验份额类别、币种和身份。现金未知使用 null，区别于 0。待确认交易、应收款和确认持仓分开。投影可重建，原始事件保留。

## 行情与预测

行情字段和严格验证见 market.py。公开发布时间、实际可得时间、采集时间分开；今天下载不自动证明历史可得。Forecast/Settlement 使用不同不可变记录类型和证据 ID。经验版本与建议引用预测和数据证据；通知意向/回执独立记录。

## 私有云快照协议

1. 通过 SQLite backup 生成一致备份，不直接复制运行中的 WAL 主文件。
2. 打包账本、报告、原始来源、模型/配置版本、审校及通知状态，生成逐文件 SHA-256 manifest。测试快照显式 test_only=true，生产拒绝恢复为正式状态。
3. 上传不可变快照至私有 Library，回读字节验证；新独立执行恢复后核对哈希及 SQLite 完整性。
4. HEAD 保存 snapshot_library_id、SHA-256、run_id、project、实际运行状态；用预期版本进行条件替换。冲突不覆盖，先恢复最新状态。
5. 仅在全流程成功并保存后推进 success；部分完成保留可追踪缺口，失败不推进。通知结果未知保留人工/平台核查状态。

暂存路径没有长期可靠性保证。Library 多文件不是原子事务；采取先不可变快照后单文件 HEAD 发布。平台持久化、真实跨定时执行恢复和通知需分别验收。禁止清理失败经验、未完成状态或未经授权删历史。

## 校准与终态撤销

变化快照必须显式 reconcile=True，事件记录 before/after、previous_version 和差异；早于最新资产事件的快照拒绝。历史重放必须显式提供真实 occurred_at，不把接收时间冒充交易时点。cancel_trade 仅用于已核实取消/拒绝终态的未确认申请，释放对应冻结资源，禁止撤销已确认交易。

通知所有可发送意向必须提供含时区 valid_until，超过24小时的意向先拒绝；发送领取前再查有效期，过期保留记录但不发送。24小时是出站队列安全期限，非任何基金交易规则。

## 每日编排发布与恢复

DailyRunner 的两阶段发布先保存已检查报告与检查点，再使用适配器验证发布回执，最后记录成功。最终检查点尚不含之后的 run.succeeded；跨任务恢复须同时取得该 manifest 和已核验独立提交回执，并执行 recover_committed，核对文件哈希及原 run 元信息后幂等重建成功。缺提交回执不能推断成功或释放通知。生产适配器必须将 manifest 与回执提交到版本化私有 HEAD，当前未内置该服务。

恢复到不同工作区时可显式传 local_paths 映射报告和检查点的新路径；逐组件拒绝符号链接，核对私有权限及原始哈希。映射只改变读取位置，原 manifest/回执/成功事件不变，返回结果另列本地位置。
