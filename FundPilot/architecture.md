# FundPilot 架构调研与技术选型记录

调研日期：2026-10-23。范围：用户完整需求、四个指定项目的官方仓库/文档/论文及关键实现，场外基金交易约束与验证方法。本文件只记录调研结论；实现、测试与部署状态另见 VALIDATION.md。

## 一、核心结论

建议采用 **确定性账本 + 事件驱动场外基金模拟器 + 简单数值基线 + 按需调用 LLM 的证据研究层**。七个职责是逻辑模块，不需要七个独立大模型。

- TradingAgents：借鉴多空证据对照、风险复核、到期反思；不直接采用其股票交易逻辑与未经统计验证的文字经验。
- Microsoft Qlib：借鉴数据/特征/模型/策略/评估解耦和实验记录；作为第二阶段可选研究适配器，不强制进入第一版运行依赖。
- FinRobot：借鉴金融文本工具、结构化研究与计算/叙述分离；不嵌入其自动代码执行默认配置。
- FinRL：借鉴环境与策略分离、公平评估；第一版不采用强化学习。其股票环境不能直接充当支付宝基金结算器。
- 先实现可信资金状态、历史时点数据、费用与结算，再比较预测模型。所有复杂方法必须通过相同资金池、相同交易约束、相同净成本的样本外比较。
- 近半年数据可以启动工程回放，通常不足以验证跨市场状态的稳定投资优势。历史 LLM 预测还有预训练知识污染风险，不能仅凭“禁止未来信息”的提示词宣称解决。

以上是针对有限本金、封闭资金池、低频场外基金的工程判断；没有声称已经产生或证明超额收益。

## 二、用户约束如何改变架构

1. 初始资金只能来自首次确认快照。潜在追加资金保留在私有授权信息中，默认不属于可用资产。
2. 资金池用途与生活费预留由私有政策明确，不公开账户财务安排；不强制满仓。风险阈值、期限和可承受亏损必须由用户确认。
3. 份额、估算市值、冻结现金、待确认申购、赎回应收、已到账现金必须分开。资产总额增加不等于可花现金增加。
4. 交易申请、受理、确认、到账是不同事件。未知日期或规则不能由模型猜测。
5. 只生成建议；任何模块均无真实下单权限。
6. 每日研究不等于每日交易。持有/不操作是正常结果。1 日预测主要用于风险监测，5/20 日预测也需通过费用与持有期过滤。
7. 真实持仓、截图、流水、预测、经验、报告必须放在私有持久层；公开仓库只放定义、代码、测试与合成样例。
8. 已验证同一云主机上独立任务从私有 Library 恢复 TEST 快照；尚未验证跨日定时运行、跨主机恢复、平台静默或真实条件通知，部署验收须单独执行。

## 三、四个项目的证据与选型

### 3.1 TradingAgents

**来源事实**：论文设计分析师、多空研究者、交易者和不同风险观点，使用辩论与共享结构化状态。实验为 2024 年第一季度科技股，比较持有和若干技术策略；该结果属于论文报告，不能外推为中国场外基金有效性。[论文 v7](https://arxiv.org/html/2412.20138v7)

当前官方 README 描述到期决策结算、基准超额收益反思和可选检查点；关键 graph 实现区分快/深模型，并限制辩论与工具轮数。[官方说明](https://github.com/TauricResearch/TradingAgents/blob/main/README.md)；[graph 实现](https://raw.githubusercontent.com/TauricResearch/TradingAgents/main/tradingagents/graph/trading_graph.py)

**适配建议**：保留“支持证据/反对证据/缺失信息/失效条件”四栏；仅在重要新信息、候选交易或分歧超过阈值时执行一次对照复核。风险规则程序化否决权高于 LLM 结论。反思只生成候选假设，进入独立检验队列。不能把多角色赞成比例映射为上涨概率。论文的股票、短样本、历史 LLM 条件与基金环境差异很大；只据此选择研究工作流，不依据其收益数字选择策略。

### 3.2 Microsoft Qlib

**来源事实**：论文把数据、模型管理、组合生成、订单执行和分析拆分；数据文档提供 loader、handler、dataset、处理器及缓存。[论文](https://arxiv.org/html/2009.11189v1)；[数据框架](https://qlib.readthedocs.io/en/latest/component/data.html)

官方 Alpha158/360 handler 为处理器设置拟合起止时间；默认预测标签使用未来 close 引用，属于监督学习目标，不能进入推理特征。[handler 实现](https://raw.githubusercontent.com/microsoft/qlib/main/qlib/contrib/data/handler.py)

**适配建议**：第一版自行维护小型可审计数据表与 pandas/numpy/scikit-learn 研究接口；资产与历史规模扩大后，再用 Qlib 管理特征实验。默认股票池、OHLCV 因子、股票交易成本不能直接用于基金。基金缺少盘中 OHLCV 时，不伪造这些字段。Qlib 的时间分段能力不自动保证新闻可用时间、基金公告修订版本、基金存续历史无泄漏。必须由 FundPilot 适配器落实。

### 3.3 FinRobot

**来源事实**：原始论文介绍金融代理、模型/工具层、LLMOps/DataOps、市场预测和文档应用。[论文](https://arxiv.org/html/2405.14767v1)

调研时官方仓库已区分 V0 教育 AutoGen、V1 Web 与 V2 桌面研究；README 强调计算由代码完成、叙述由 LLM 辅助。这是维护者定位，尚未经本项目部署验收。[官方仓库](https://github.com/AI4Finance-Foundation/FinRobot)

V0 `SingleAssistant` 通过 UserProxyAgent 连接工具，默认自动回复上限 10，默认代码执行配置 `use_docker=False`。[workflow 实现](https://raw.githubusercontent.com/AI4Finance-Foundation/FinRobot/master/finrobot_autogen/finrobot/agents/workflow.py)

**适配建议**：复用证据抽取和结构化摘要思想，控制输出为事实、观点、推断、未证实假设。拒绝运行新闻/网页要求执行的代码。生产研究工具使用只读白名单与严格 schema；任何研究代码均须独立沙箱，不挂载私有账本和凭据。个股 DCF/财报估值对普通基金的直接价值有限，只在底层集中暴露的专项研究中选择性使用。整套桌面系统对本任务过重。

### 3.4 FinRL

**来源事实**：官方论文和文档采用市场环境、DRL 代理、应用分层，强调摩擦与基准；FinRL-Meta 分开训练、调参与后续回测/交易阶段。[论文](https://arxiv.org/html/2011.09607v1)；[架构](https://finrl.readthedocs.io/en/latest/start/three_layer.html)；[DataOps 与流水线](https://finrl.readthedocs.io/en/latest/finrl_meta/overview.html)

关键 `StockTradingEnv._sell_stock` 将卖出金额立即加到现金状态，并采用买卖比例费用参数。[环境实现](https://raw.githubusercontent.com/AI4Finance-Foundation/FinRL/master/finrl/meta/env_stock_trading/env_stocktrading.py)

**适配建议**：该实现对基金赎回应收和到账延迟不够，若直接使用会让未到账资金重新买入。有限历史、少量基金、稀疏交易与高样本相关性，也使 RL 增加过拟合和调参成本。第一版不引入 RL；未来若研究，必须先替换环境为经独立测试的基金模拟器，锁定奖励与训练预算，再以完全相同条件比较简单策略。真实账户不用于在线探索。

## 四、推荐模块与最小运行闭环

以下均为本项目设计建议。

| 模块 | 确定性职责 | 可选 LLM 职责 |
|---|---|---|
| PortfolioManager | 金额/份额精度、快照、流水、状态机、差异校准 | 截图字段提取并附原始位置、置信度 |
| MarketResearch | 来源抓取、去重、时点过滤、公告版本 | 新闻与持仓关联、结构化证据摘要 |
| ForecastEngine | 数值特征、模型、滚动回放、预测冻结 | 独立实验性文本情景 |
| ExperienceManager | 到期结算、统计比较、版本与状态流转 | 提出误差假设，禁止直接晋升规则 |
| RiskAdvisor | 可用现金、限制、成本、集中度、风险闸门 | 解释候选方案与分歧 |
| Validator | schema、时间、资金守恒、数据完整性、来源检查 | 高价值报告的事实复核 |
| NotificationManager | outbox、幂等、去重、有效期、发送状态 | 用已核实字段生成简洁提醒 |

建议每日流水线：获取数据 → 校验 → 账本事件处理/估值 → 到期预测结算 → 数值预测 → 风险计算 → 必要时文本研究 → 候选建议 → Validator → 保存完整记录 → 有条件写通知 outbox。没有新净值的节假日也可核对公告和到期状态，不能凭空造交易日数据。

每日、每周、每月任务共享私有数据库，分别带 run_id、input_hash、policy_version、status。运行失败不得更新 last_success。恢复时只重试未完成步骤，唯一键防止重复结算或重复通知。

初期可用事务型数据库保存账本与索引，文件/对象存储保存原始证据、市场快照和报告。SQLite 在临时环境中仅作工作副本；每次以一致备份、哈希校验和版本条件替换发布到获授权私有持久存储，不能依赖临时磁盘持续存在。使用事务、单写者锁或数据库并发控制、备份、迁移版本与恢复演练。哈希能检测修改，不能单独保证管理员不可改；正式冻结还需追加式权限或独立备份证据。

## 五、场外基金模拟器和费用

### 5.1 已核实的规则边界

基金管理人投教说明：净值计算已计提管理、托管及适用的销售服务费；境外产品还受海外收市时间和汇率影响。[易方达净值说明](https://edu.efunds.com.cn/c/44/44051.shtml)

管理人说明场外基金采用未知价，截止时点影响申请归属日；其中给出的普通基金/QDII 确认示例只能作为示例，不能作为所有产品统一规则。[金鹰基金交易问答](https://www.gefund.com.cn/main/khfw/cjwt/jyl/a/20200604/10159250.html)

**重要时效变更**：证监会新版《公开募集证券投资基金销售费用管理规定》自 2026-01-01 施行。官方发布说明涉及费率调整、赎回费用、长期持有销售服务费等。当前费率模型不能硬编码旧规则；历史回测也不能将新规回填到旧时期。[正式公告](https://www.csrc.gov.cn/csrc/c101954/c7606091/content.shtml)；[修订发布说明](https://www.csrc.gov.cn/csrc/c100028/c7606047/content.shtml)

公告、发布说明及随后取得的官方规则原文核对范围见 fund-trading-rules.md；不声称涵盖所有法规适用情形。具体基金、支付宝渠道费率和实际到账时间仍须按账户实际资料核实。

### 5.2 设计要求

- `fund_rules` 按完整基金代码、份额类别、渠道、valid_from/valid_to、公告可用时间版本化；证据保存原件与 hash。
- 交易记录包含申请时间、渠道受理时间、适用 T 日、净值日、确认日、实际到账日、份额批次和对应规则版本。
- 买入冻结现金；确认后按实际净申购额/净值确认份额；失败时退款单独入账。
- 赎回先锁定份额，确认后转为应收；实际到账才释放现金。卖出确认后与到账前，资产包含应收但可用现金不变。
- 赎回费必须按适用份额批次和真实持有期分档，遵循产品的批次扣减规则。不得默认所有基金 FIFO。
- 用真实净值回测时，不重复扣管理/托管/已反映的销售服务费；独立扣除尚未在净值内体现的个人申赎、转换等费用。
- 区分单位净值、累计净值和经核实的总回报序列；不能把累计净值直接当作可成交价格，也不能将分红除息当作单纯亏损。
- 现金分红进入应收/到账状态；红利再投资按公告规则增加份额。总回报基准与真实账户分红选择需明确区分。
- A/C 选择比较整个预期持有期、真实折扣和批次规则；没有统一“短期 C 长期 A”的自动决策阈值。
- QDII 使用基金开放日历、境外市场日历、时区、净值发布时间与汇率口径；不得把后公布的净值放入较早决策。
- 保留限购、暂停申赎、最低申购/最低持有、巨额赎回延迟、锁定期和转换能力等约束。
- 规则未知时，研究仍可运行，正式金额建议必须阻断或以明确的保守情景报告，不能展示为可执行确定结果。

## 六、未来泄漏与 LLM 知识污染

### 6.1 三个独立时间层

每条数据至少保留：`observation_time`（经济/净值归属时间）、`published_at`（来源发布时间）、`available_at`（可用于决策的证据时间）、`ingested_at`（系统实际抓取时间）、版本与来源。

回放的可见集必须满足 `available_at <= decision_cutoff`。如今才抓到的旧网页若没有历史归档证据，不能仅据网页标注日期证明当时内容完全相同。宏观修订值、基金季度披露、新闻改稿均保存版本；缺少历史版本时排除相关特征或标记无法审计。

训练标签可用未来实现值，但训练样本只有在标签已到期、实际值已可获取后才可使用。20 日标签与相邻样本高度重叠；分折需 purge 掉标签跨界样本，并采用预先定义的隔离期。归一化、缺失值处理、特征筛选和概率校准都仅用训练/验证段拟合。

### 6.2 预训练污染无法靠提示词根除

研究对 LLM 记忆经济/金融历史值及历史预测可信度提出实证警告。[The Memorization Problem](https://arxiv.org/abs/2504.14765)；另有专门比较时段与量化基线的前视偏差基准。[Look-Ahead-Bench](https://arxiv.org/abs/2601.13770)

本项目应分离三条证据轨道：

1. **可审计数值历史回测**：不用当前 LLM 为过去补生成标签、因子或预测理由；只依赖当时数据及当时已训练的数值模型流程。
2. **受污染风险的 LLM 历史研究**：用于功能、摘要与提示测试；明确标注回溯生成，不能称为当时冻结预测，更不能单独支持实盘交易。
3. **真正前向模拟**：今天生成、时间戳冻结、未来结算；锁定模型/提示/数据/规则版本，持续比较同期基线。

匿名化、删除日期、提示忽略未来、RAG 时间过滤只能减少部分外部泄漏，不能证明参数内没有历史记忆。即使提供模型知识截止日期，也需确认该版本训练与后续更新边界；无法确认就维持污染警示。历史成功反思不得回流到发生更早的回放日。

## 七、模型、基准和验证协议

### 7.1 模型递进

- 起步：零收益/历史均值、简单趋势或动量、滚动波动区间、逻辑回归/岭回归。
- 验证后：小规模树模型、少量宏观/资产因子；限制参数搜索预算。
- 暂缓：深度时序网络、RL、自由生成策略、多 Agent 每日全量辩论、大规模因子挖掘。
- 优先输出校准过的区间；概率样本不足时明确不输出数值概率。
- 允许 abstain（不作预测）；记录覆盖率，防止只展示有利样本。

### 7.2 公平基准

相同初始资产、基金集合、现金、费率、时间规则、分红口径与数据可见集下比较：原持仓长期持有；固定比例低频再平衡；封闭池内预定分批投入；简单趋势/动量；适配资产暴露的相关指数/组合。指数是参考基准时明确其不可直接交易或费用差异。

封闭池定投只能拆分初始现金；钱用完就停止。用户确认的新增资金在相同日期同步进入所有可投资基准。未经确认的潜在追加资金不能进入任何基准。已有持仓纳入基准起点，不假设免费清仓重建。

### 7.3 Walk-forward

先登记目标、模型列表、主指标、训练/验证/测试边界、费用情景与调参次数。外层按时间滚动；内层仅调参与校准；最终保留一段不参与模型选择的测试。固定日历按各基金交易日解释 1/5/20 日；记录预测终点及净值可获取后的实际结算时间。

指标：方向正确率与类别基线；MAE/RMSE；Brier/log loss 与可靠性分组（有概率时）；区间覆盖率、区间宽度；扣费净收益、回撤、波动、风险调整表现；换手、交易次数、资金闲置/冻结时间、实际元金额收益与成本。

短样本年化指标仅辅助，不用漂亮年化数掩盖样本短。采用适合时间依赖的块抽样/稳健误差估计，报告不确定性；多策略多特征搜索计入多重比较。样本足够的门槛按所需效应、功效与相关性确定，不指定任意“胜率达标即可上线”。

六个月大约只覆盖少量不重叠 20 日窗口，无法把逐日滚动的重叠结果当作大量独立证据。初期输出“证据不足、继续前向模拟”完全符合目标。

## 八、经验学习和风险建议闸门

经验状态：候选 → 验证中 → 暂时有效 → 降权/失效/停用 → 归档。保存全部反例和旧版本，禁止删除失败历史。每条经验关联产生它的训练样本、独立验证样本和未来测试样本；发现经验的案例不能重复计入独立验证。

月审先运行统计与漂移检查，再允许 LLM 写解释。正确预测只说明该次结果，不能证明因果。归因分为可核实数据故障、事件证据、假设变化和未解释误差。新策略作为 challenger 影子运行，经过预定比较后才替换 champion；重大风险策略变化需用户批准。

候选建议必须依次通过：用户风险参数齐全 → 资产/现金已校准 → 数据足够新 → 交易规则可验证 → 预测/经验适用 → 净价值有意义 → 集中度与回撤/流动性情景合格 → 用户可在有效期内自行操作。任一项失败，输出不操作或一次性校准请求。

交易价值按预计金额收益减申赎/转换费用、资金延迟影响及不确定性缓冲比较，并呈现悲观情景。模型/API 支出单独作为系统运行成本跟踪；不要偷偷从基金净值中扣除，也不能忽略它对小本金使用价值的影响。最大回撤约束是风险监控与情景约束，不能保证未来净值跳变时永不超限。

## 九、调用成本与低打扰

- 数值估值、回测、预测结算和报表指标全部程序化。
- 新闻按持仓暴露筛选，先 hash 去重、规则摘要、同事件聚合，再按需 LLM。
- 缓存键包含来源版本、数据 cutoff、模型/提示版本；历史回放缓存不能混入未来摘要。
- 每次运行设 token、工具轮数、重试和费用上限；耗尽预算降级为确定性风险检查，不无限重试。
- 通知建议指纹使用基金、原因、动作、策略版本、有效期及重要变化字段；提醒送达与业务状态采用 outbox 分离，发送不明时先查状态再重试。
- 每周/月内部报告默认仅保存。平台“任务完成通知”与业务提醒是两个机制，必须端到端实测静默；提示词无法替代平台能力验证。

## 十、验收与待解决事项

最低工程验收：资金状态守恒；赎回未到账不得买入；分红/复投正确；持有期费率边界；新旧费率跨生效日；QDII 日历/延迟；截图缺失现金不猜测；过期数据阻断；未来新闻与训练标签注入被拒绝；预测冻结及更正追加；重复任务幂等；失败不标成功；恢复不丢记录；通知去重；公开仓库秘密扫描。

真实能力验收单列：独立定时任务跨次读写、进程中断恢复、备份恢复、正常完成无业务提醒、条件触发实际到达。这些均不能用单元测试替代。

尚待：用户基金代码与份额类别、支付宝实际费率和批次/确认规则、风险期限/亏损承受度、真实历史净值与分红质量、历史资讯时点档案、数据使用许可、私有持久服务与运行预算、平台静默机制。它们不阻止合成数据基础工程，但会阻止声称已形成个性化正式投资策略或已上线。
