# 执行流程

1. 从私有云 HEAD 读取已校验快照；核对项目、哈希、版本、ledger 完整性、上次状态。检查 GitHub 已批准 commit 及定义变化。账户流程无状态时停止，不创建空账户假装首次使用；非个性化观察池可独立记录公开研究证据，不生成账户状态。
2. 固定本轮开始/数据截止时间与 run_id。恢复未完成记录、通知意向与待确认交易。对读写版本使用冲突检查；冲突不覆盖。
3. 按 information-policy.md 登记用途、优先级、对象、截止和缺口；个性化任务读取真实持仓和风险参数，通用研究使用明确样本，并按 portfolio-policy.md 分层记录持仓外观察池、可买入候选与已确认持仓；筛选保留费用、风险、暴露重叠、申赎限制、证据日期及缺口。按需求获取公开净值、公告和相关资讯；只读复用 NewsChaser 中有出处的材料，不足部分独立补查。
4. 各数据保存事件日期、发布时间、实际可获取时间、抓取时间、URL、原始字节哈希、版本和核实边界。净值日期与当前日期分开。过期或冲突阻止相关建议。
5. 估值与现金核对。结算已到期且目标交易日证据齐备的旧预测。未到期和缺数据不能当作失败预测。解释区分事实、模型推断和待验证假设。
6. 按 backtesting.md 最小协议，由当前真实 LLM 综合检索证据、新闻/政策/市场与基金暴露，形成附引用、反证、失效条件和未知项的条件预测；与固定数值基线分别标识、冻结后再评分；mock单列为工程测试。无条件方向与条件情景分别评，报告覆盖率/弃权率及成熟命中率，禁止后选情景。证据不足时弃权，主观置信不作校准概率。研究结果在证据、费用、可交易性、风险与真实资金闸门之后才能转为建议。
7. 按基金、份额、渠道与有效日期核对费用、确认、到账、限购、节假日等。只建议值得承担成本和风险的动作。正常决策可以不操作。
8. 将发现的问题与证据、归因候选、单变量修改、冻结协议及复验结果串联记录，保留反例，按 experience-policy.md 审查；更新经验与每日报告；在到期周/月运行回顾。研究模型不得自行升级正式策略。统计检验和策略变更均留版本及证据。
9. 事实检查、TextReadable 审校与结构检查。将正文及审校结果私有持久化，回读核验后提交 HEAD。成功、部分完成、失败分别记录，失败不推进成功状态。
10. 将符合通知条件的意向写入 durable outbox；保存发送回执、未知结果与确认状态。结果未知先查询，不盲重试。常规无行动仅保存，不发消息。

上述是目标完整流程。每个步骤的当前实现与尚未接通环节以 VALIDATION.md 为准；指令文档不代表服务已运行。
